ext4 On-Disk Reference Table

Lab 4 challenge 3 uses an ext4 volume image. Locate a filename in the directory, take its inode number, inspect the inode, and follow its block mapping to the file content. Most multi-byte fields shown are little-endian.

Superblock and block group

The primary superblock starts at byte 1024 from the beginning of the ext4 volume. Directory entries point to inodes, whose records live in block-group inode tables. Inode 2 is the root directory. Inode numbering starts at 1.

Offset (from structure start)SizeFieldWhy it matters
0x184s_log_block_sizeBlock size = 1024 << value.
0x284s_inodes_per_groupFind group from (inode − 1) // value.
0x382s_magicExpected little-endian 53 EF (0xEF53).
0x582s_inode_sizeSize of an inode table record.

For the selected block group, the group descriptor gives the inode table block (low 32 bits at group-descriptor offset 0x08). The index within that group is (inode − 1) % inodes_per_group. Locate the actual descriptor using block size and filesystem features; 64-bit descriptors can include high address words.

Extent header and leaf

When extents are enabled, i_block begins with extent header magic 0xF30A (bytes 0A F3). Header offsets: 0x00 magic (2), 0x02 entries (2), 0x04 max (2), 0x06 depth (2). For depth zero, each 12-byte leaf extent has logical start block at 0x00 (4), length at 0x04 (2), physical start high at 0x06 (2), and physical start low at 0x08 (4). A nonzero depth means follow index nodes. debugfs -R "ls -l /" image.raw, debugfs -R "stat /name" image.raw, and debugfs -R "cat /name" image.raw help verify a manual parse.

ext4 deletion behavior depends on allocation, journaling, and features. Do not assume deleted inode block mappings survive.
