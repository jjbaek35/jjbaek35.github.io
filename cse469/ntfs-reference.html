NTFS VBR and MFT Reference Table

Lab 4 challenge 6 uses a synthetic raw NTFS structure image with a VBR and selected MFT records; it is not a mountable full volume. NTFS starts at a volume boot record (VBR); the MFT holds file records and typed attributes.

$FILE_NAME value

Within the resident $FILE_NAME value, the filename length is at relative 0x40 (1 byte), namespace at 0x41 (1 byte), and UTF-16LE filename begins at 0x42. The first eight bytes hold the parent directory file reference. A resident $DATA value starts at the offset recorded in its own attribute header. Do not assume every NTFS $DATA attribute is resident.

Attribute and allocation clues

Each attribute has type at relative 0x00 (4 bytes), total length at 0x04 (4), and resident/nonresident flag at 0x08 (1). Examples: 0x10 $STANDARD_INFORMATION (timestamps), 0x30 $FILE_NAME (name and parent link), 0x80 $DATA (content), 0x90 $INDEX_ROOT (directory index). Small resident data can be inside the MFT record; nonresident attributes reference clusters through data runs. $Bitmap tracks volume cluster allocation, while MFT record flags describe individual records. Deletion may clear allocation metadata without immediately overwriting data; recovery depends on reuse and overwrite.

$LogFile is the NTFS transaction log; $Extend\$UsnJrnl is the separate change journal. They should not be treated as the same structure.
