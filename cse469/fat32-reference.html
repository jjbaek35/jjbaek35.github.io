FAT32 Allocation and Directory Reference

Lab 4 challenges 2, 4, and 5 analyze FAT32 volume images. Offsets below are relative to the start of the volume image; a whole-disk image requires the partition byte offset as well.

Allocation formulas

FirstDataSector = ReservedSectors + FATCount × SectorsPerFAT
FATEntryByteOffset(n) = ReservedSectors × BytesPerSector + n × 4
ClusterFirstSector(n) = FirstDataSector + (n − 2) × SectorsPerCluster
ClusterByteOffset(n) = ClusterFirstSector(n) × BytesPerSector

FAT32 entries are 32-bit little-endian; only the low 28 bits are the cluster value: entry & 0x0FFFFFFF. Values 0x0FFFFFF8 through 0x0FFFFFFF mean end of chain; zero indicates a free cluster. Follow the FAT rather than assuming clusters are adjacent.

Deletion and slack

When a short directory entry begins with E5, its former first character is generally unavailable from that entry. The starting cluster and size may remain, while the FAT chain may have been cleared. Residual data can persist until overwritten; recovery is not guaranteed.

Drive slack = allocated cluster bytes − logical file size. The bytes from EOF to the next sector boundary are often called RAM slack in the lecture; the remaining allocation up to the end of the cluster is file slack. Their contents vary with filesystem implementation and writes. Lab 4 provides deliberate bytes in file slack.
